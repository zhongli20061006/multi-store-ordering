# 大阶段计划

## 阶段一：本地原型（当前）

目标：跑通「顾客小程序点单 → 商家后台接单 → 本地数据落库」的完整闭环，验证多门店模型。

### 子阶段

| 子阶段 | 交付物 | 完成标准 | 验证 |
| --- | --- | --- | --- |
| 1.1 后端骨架 | FastAPI 服务、健康检查、SQLite、种子数据 | 服务可启动，/health 返回 ok，库中有门店/菜单种子 | 启动命令 + 接口请求 |
| 1.2 数据模型与 API | 门店/菜单/订单/登录 API | 全部接口按合同工作，金额由后端计算 | 接口自动化测试 + 手工请求 |
| 1.3 商家后台 | 登录、门店、菜单、订单页面 | 商家可完成全部管理操作 | 浏览器走查 |
| 1.4 顾客小程序 | 门店列表、菜单、购物车、下单、我的订单（含扫码直达入口） | 顾客可完成完整点单 | 微信开发者工具走查 |
| 1.5 联调与验收 | 全流程贯通 | 顾客下单 → 后台接单 → 状态变化可见 | 端到端走查 + 验收清单 |

### 本阶段非目标

在线支付、微信登录、美团/抖音核销、部署上线、营销/会员/库存/配送。

## 阶段二：支付与上线准备（后续）

- 微信登录（code2session）与顾客身份
- 微信支付下单、回调、退款边界
- 正式部署：服务器、域名、小程序企业主体 AppID、微信支付商户号
- 进入本阶段前需用户提供/确认资质，并重新核查官方文档

## 阶段三：美团/抖音团购券核销（已确认的下一阶段）

- 商家后台新增「券核销」入口：输入/扫码美团或抖音券码
- 调用美团/抖音开放平台商家接口核销并落库留痕
- 进入本阶段前必须核查平台官方文档、资质、沙箱与费率，本阶段不受现架构阻碍

## 阶段四（可选，未确认）

- 抖音点单小程序客户端等：若确认，客户端迁移跨端框架，后端接口不变（触发条件见 technical-selection.md）
