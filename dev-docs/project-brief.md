# 项目简报

## 项目摘要

多门店线上点单小程序：顾客通过微信小程序选择门店、浏览菜单、下单（本阶段不收款，到店付款），商家通过网页后台管理门店、菜单和订单。第二阶段接入美团/抖音团购券核销——顾客在美团/抖音购买的团购券，到店后由店员在本系统核销。

当前阶段为本地原型开发，不上线、不接支付、不接第三方平台。

## 目标用户与场景

- 顾客：到店前先用小程序看菜单、提前点单，到店取餐/堂食，省去排队等待；原型期以商家熟人/测试用户为主。
- 店主/店员：在网页后台维护门店与菜单、接单、更新订单状态、查看订单；第二阶段在此核销美团/抖音团购券。
- 使用场景：多门店连锁或单店多门店商家，顾客按门店点单。

## 产品流程与 MVP 核心流程

MVP 核心闭环（顾客侧）：

1. 打开小程序 → 选择门店（或扫门店二维码直接进入该店菜单）
2. 浏览该门店菜单（分类 + 商品）
3. 加入购物车 → 填写联系人、电话、备注
4. 提交订单（不支付）
5. 商家后台看到新订单 → 接单 → 出餐 → 完成
6. 顾客可凭电话查询自己的订单状态

商家侧闭环：登录后台 → 管理门店/菜单 → 处理订单（接单/完成/取消/标记到店付款）。

## 功能边界

### 第一版（原型，本阶段）

- 顾客端：门店列表、门店菜单、购物车、提交订单、订单成功页、按电话查订单、到店扫码点单（二维码携带门店参数直达菜单，与提前点单共用下单流程）
- 商家端：账号登录、门店管理（增删改、营业状态）、菜单管理（分类、商品增删改、上下架）、订单管理（列表、筛选、接单/完成/取消、标记付款）
- 后端：门店/菜单/订单/登录相关 API、本地数据库、种子数据

### 明确不做（本阶段）

- 在线支付（微信支付）
- 微信登录（openid 换取）
- 美团/抖音团购券核销
- 外卖配送、配送费、起送价
- 会员、积分、优惠券、营销活动
- 库存管理
- 多语言、多币种
- 真实上线部署

## 演进边界

| 类别 | 内容 | 说明 |
| --- | --- | --- |
| current_required（本阶段必须） | 多门店点单核心闭环 + 简单商家后台 | 用户已确认 |
| confirmed_next（已确认下一阶段） | 美团/抖音团购券核销 | 用户已确认方向；具体平台 API 与资质在实施该阶段前另行核查 |
| must_not_block（不得堵死） | 在线支付、微信登录 | 用户明确原型期不做，但订单模型保留支付状态字段，登录模型保留 openid 字段 |
| explicit_non_goal（明确不做） | 外卖配送、会员营销、库存 | 见功能边界 |
| speculative（猜想，不做架构约束） | 抖音/支付宝点单小程序客户端 | 未确认需求；若确认，客户端需迁移跨端框架，后端接口不受影响 |

## 数据与业务对象

- 管理员用户（商家账号）
- 门店（store）
- 菜单分类（category）
- 商品（item）
- 订单（order）与订单明细（order_item）
- 支付状态字段（本阶段仅占位，到店付款）
- 第二阶段新增：核销记录（voucher redemption）

详见 [database-design.md](database-design.md)。

## 初始产品形态判断

三端：微信小程序（顾客）+ 网页管理后台（商家）+ 后端 API 服务（本地运行）。本阶段全部在本机运行，无需真实小程序 AppID（微信开发者工具测试号即可）。

## 初始技术路线判断（未定稿，待选型确认）

- 小程序：微信原生开发（测试号可运行）
- 商家后台：Vue 3 + Element Plus 网页应用
- 后端：Python FastAPI + SQLAlchemy + SQLite（本地），未来可切 PostgreSQL
- 详见 [technical-selection.md](technical-selection.md)

## 同类产品参考

常见参考：瑞幸/蜜雪冰城/古茗等小程序点单流程（选店 → 菜单 → 购物车 → 下单），美团/抖音来客的商家核销流程。

- 值得学：极简点单路径、按门店隔离菜单、订单状态清晰。
- 不照搬：大厂复杂会员体系、营销玩法、配送体系（本阶段明确不做）。
- 本项目差异：聚焦小商家多门店场景，原型轻量、无支付，先跑通点单闭环再扩展核销。

## 差异化 / 产品价值

一个系统同时覆盖：自家小程序点单 + 后续美团/抖音团购券核销，减少商家在多个工具间切换；多门店数据统一管理。

## 后续里程碑

2. 微信支付 + 正式上线准备（需企业主体/商户号，另行确认）
3. 美团/抖音团购券核销（需平台资质，另行核查官方文档）

详见 [stage-plan.md](stage-plan.md)。

## 验收规则

原型验收 = 顾客端完整点单一单成功 + 商家后台能接单改状态 + 本地数据落库可查 + 权限边界正确。具体验收清单见 [acceptance.md](acceptance.md)。
